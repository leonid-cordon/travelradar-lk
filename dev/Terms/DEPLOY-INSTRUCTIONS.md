# Как развернуть синхронизацию для AI Terms
### Пошагово, по тому же принципу что и daily-ops

---

## Что в итоге получится

```
ПК      → [браузер] → ai-terms-api (Worker) → AI_TERMS_STORE (KV) → одна копия данных
Ноут    → [браузер] → ai-terms-api (Worker) → AI_TERMS_STORE (KV) → та же копия!
```

Полностью отдельно от `daily-ops` и `DAILY_OPS_STORE` — ничего там не трогаем, не сломаем.

---

## Шаг 1 — создать KV namespace

`Cloudflare Dashboard → Storage & databases → KV → Create namespace`

Название: **`AI_TERMS_STORE`**

Это создаёт пустое хранилище — как пустую папку.

---

## Шаг 2 — создать Worker

`Workers & Pages → Create application → Worker → Start with Hello World`

Название: **`ai-terms-api`**

После создания у тебя будет адрес вида:
```
https://ai-terms-api.ТВОЙ-ЛОГИН.workers.dev
```
(тот же логин, что и в `daily-ops-api.leonid-cordon.workers.dev` — просто другое имя Worker'а)

---

## Шаг 3 — привязать KV к Worker (Binding)

`Worker ai-terms-api → Settings → Bindings → Add binding → KV namespace`

```
Variable name: AI_TERMS_STORE
KV namespace:  AI_TERMS_STORE
```

---

## Шаг 4 — вставить код Worker'а

`Worker ai-terms-api → Edit code`

Скопируй содержимое файла `ai-terms-worker.js` (прислал отдельным файлом) и полностью замени им код-заглушку "Hello World".

**Перед сохранением — поменяй токен.** В начале файла есть строка:
```javascript
const TOKEN = 'ai-terms-secret-2026-change-me';
```
Замени `ai-terms-secret-2026-change-me` на свою собственную секретную строку — любую, главное чтобы её не угадали (например `мой-личный-токен-xk29fz`). Сохрани (`Deploy`).

---

## Шаг 5 — вписать адрес и токен в `terms.html`

Открой `terms.html`, найди (ближе к началу `<script>`):

```javascript
const WORKER_URL   = 'https://ai-terms-api.ТВОЙ-ЛОГИН.workers.dev/terms';
const WORKER_TOKEN = 'ai-terms-secret-2026-change-me';
```

Поменяй:
- `ТВОЙ-ЛОГИН` — на свой реальный логин Cloudflare Workers (тот же, что в адресе `daily-ops-api`)
- `ai-terms-secret-2026-change-me` — на тот же токен, который ты вписал в Worker на шаге 4 (должны совпадать **дословно**, в обоих местах)

Сохрани файл.

---

## Шаг 6 — выложить на сайт

Так же как `daily-ops.html` лежит в `dev/ToDo/`, положи `terms.html` куда-то рядом, например:

```
GitHub: leonid-cordon/travelradar-lk
└── dev/ai-terms/terms.html
```

После `git push` Cloudflare Pages задеплоит автоматически (как и всегда), и страница станет доступна по адресу вида:
```
https://travelradarlk.com/dev/ai-terms/terms
```

---

## Как проверить что всё работает

1. Открой страницу, добавь любой термин.
2. Глянь в правом верхнем углу шапки — должно мелькнуть **«✓ сохранено»**.
3. Открой ту же страницу в другом браузере (или на ноуте) — новый термин должен быть уже там.

Если вместо «✓ сохранено» видишь **«⚠ офлайн»** — самые частые причины: токен в `terms.html` не совпадает с токеном в Worker-коде (проверь оба места дословно), либо `WORKER_URL` указывает не туда (опечатка в логине или в имени Worker'а), либо забыл сделать Binding на шаге 3.

---

## Важная особенность — на что обратить внимание

В отличие от `daily-ops`, где задачи получают случайный ID (`task_xxxx`), термины в AI Terms тоже теперь получают такой же случайный ID вместо порядкового номера — это сделано специально для синхронизации: если ты добавишь термин на ПК офлайн, и одновременно другой термин на ноуте офлайн, у них не возникнет конфликта одинаковых ID при последующей синхронизации.

Но сам принцип синхронизации — **«вся база целиком перезаписывается последним сохранением»**, как и в `daily-ops`. Если на ПК ты добавил термины, не успел синхронизировать (например не было интернета), и в это время на ноуте тоже что-то добавил и он засинхронизировался первым — следующее сохранение с ПК перезапишет ноутбучные правки. Для личного инструмента, которым ты пользуешься последовательно (поработал на ПК, закрыл, потом открыл на ноуте), это практически никогда не станет проблемой. Но если будешь работать одновременно на двух устройствах — об этом стоит помнить.

Экспорт через «Меню → Экспорт JSON» по-прежнему работает как обычная резервная копия — рекомендую делать его периодически независимо от облачной синхронизации.
