## 1. Что сделано в этой сессии

### A. Единое Content Menu (Hub + статьи из одного источника)
Проблема была: хабы Hub v2 показывали новую таксономию (7 пунктов), а 171 статья — legacy-меню (6 старых пунктов, вшито inline в `.article-nav-wrap`).
Решение — **третий партиал по образцу header/footer, но генерируемый**:
- Источник один: `i18n.mjs` → `switcher[]`.
- `dev/generator/build-content-menu.mjs` (новый) печёт `Partials/content-menu-{en,ru,ua}.html` (разметка `.site-nav`/`.nav-link` — её уже стилизует `assets/css/article-content.css`, нового CSS нет).
- `js/load-header.js` инъектит партиал в существующий `.article-nav-wrap` на статьях (файлы статей НЕ трогаются; legacy-`<nav>` остаётся как no-JS фолбэк). `PARTIALS_VERSION` → `2026-06-08`.
- Хабы продолжают печь то же меню из того же `i18n.mjs` через `build-sections.mjs`. Шов `ua`(папка/URL)/`uk`(код языка) решён в генераторе (файл по `folder`).
- **Активной подсветки секции на статьях нет** (сознательно отложено).

### B. `build-all.mjs` — одна команда сборки
`dev/generator/build-all.mjs` (новый) — тонкий оркестратор, вызывает существующие генераторы по порядку:
`build-index` (×3 языка) → **кросс-языковой паритет** → `build-sections` (×3×7) → `build-content-menu`.
Существующие генераторы внутри НЕ менялись (только вызываются).

### C. Убран замороженный гейт корпуса
В `build-index.mjs` был хардкод `EXPECTED_SECTIONS = {stay:22,...}` → падал на каждой новой статье.
Убран. Вместо него `build-all.mjs` после генерации сравнивает распределение секций **между языками** (en/ru/uk должны совпадать). Корпус растёт без правок кода; забытый перевод по-прежнему роняет сборку с понятным FATAL.

### D. Навык `/publish` (диалоговая публикация для владельца)
- `.claude/skills/publish/SKILL.md` (новый) — сценарий: detect → прочитать статью → предложить секцию → спросить только неоднозначное → подтвердить → insert → build-all → отчёт → предложить коммит.
- `dev/generator/registry-tool.mjs` (новый) — детерминированный помощник: `detect` / `validate` / `insert`. Сериализатор реестра **byte-stable** (проверено round-trip; массивы с `", "`). AI принимает решения, код делает опасную механику (вставка JSON).

### E. sitemap приведён в соответствие
Найден реальный недочёт миграции: в `sitemap.xml` не было 12 RU/UA Hub v2 секций (были только EN).
Добавлены 12 URL (`{ru,ua}/content/{destinations,stay,things-to-do,weather,planning,safety}/`), обновлён `lastmod` корней RU/UA до `2026-06-08`. Итог: 229 → **241** URL, XML валиден, дублей нет.

## 4. Риск-зоны после миграции (обсуждены, НЕ проверены)

Класс ошибки: «EN проверяли глазами, RU/UA приняли на доверии; проверяли генераторы по отдельности, не стыки между ними». Кандидаты на проверку, когда дойдут руки:
- hreflang-симметрия EN/RU/UA на хабах; `og:locale`/`inLanguage` на RU/UA живьём.
- Content Menu на реальной RU/UA-статье в браузере (рендер, CLS) — самое свежее, не смотрели вживую.
- no-JS фолбэк статей = legacy-меню со старой таксономией.
- breadcrumbs JSON-LD внутри статей (read-only) = старая иерархия Countries/Mexico, рассинхрон с Hub v2.
- внутренние ссылки в теле статей на legacy-разделы (битыми станут при удалении legacy).
- clean-URL: хабы со слешем `/content/stay/`, статьи без `/content/<slug>` — поведение на GitHub Pages/Cloudflare.
- повторяющийся шов `ua`/`uk` — подозревать в любом новом коде, берущем язык из URL.
