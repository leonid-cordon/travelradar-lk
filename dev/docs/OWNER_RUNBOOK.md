# Owner Runbook — Travel Radar LK

**Для кого:** владелец сайта, который умеет работать с файлами и VS Code, но не хочет разбираться во внутренностях генераторов.
**Что описывает:** полный путь публикации новой статьи — от трёх готовых файлов до собранного и проверенного сайта.
**Обновлено:** 2026-06-15 (главная страница теперь собирается автоматически — блок «Последние материалы» через `build-home.mjs` внутри `build-all`; ранее: sitemap через `update-sitemap.mjs`, Content Hub v2, единое меню, `build-all`, навык `/publish`).

> Главный принцип: ты готовишь **контент** (3 языковых файла статьи). Всё остальное — таксономию, реестр, сборку меню и хабов — делает пайплайн, по возможности через диалог с AI. Тебе не нужно открывать JSON, помнить словари или запускать генераторы по отдельности.

---

## 0. Предусловие — три файла статьи на месте

Перед публикацией у тебя должны быть созданы и сохранены **три файла с одинаковым именем** (slug), по одному на язык:

| Язык | Путь |
|---|---|
| EN | `en/content/<slug>.html` |
| RU | `ru/content/<slug>.html` |
| UA | `ua/content/<slug>.html` |

- **`<slug>`** — технический адрес статьи: латиница, через дефис, без пробелов. Пример: `best-time-to-visit-cozumel`. Он же станет URL и **одинаков во всех трёх языках** (отличаются только содержимое и папка).
- В `<head>` каждого файла должны быть: `<title>`, `og:title`, `og:description`, `og:image`, и блок JSON-LD с `"@type": "Article"` и `datePublished`. *(Если статья сделана по образцу существующей — это уже так.)*

✅ Проверь: имена всех трёх файлов **совпадают** (включая дефисы).

> ⚠️ Заголовки, описания, картинки и даты в реестр **не вписываются** — они берутся автоматически из `<head>` статьи. В реестр идёт только таксономия (секция, страна, теги).

---

## 1. Путь A (рекомендуемый) — через `/publish`

Это основной ежедневный способ. Минимум действий, ноль ручного JSON.

1. Сохрани 3 файла статьи (см. раздел 0).
2. В Claude Code набери:
   ```
   /publish
   ```
3. Дальше — диалог. AI сам:
   - найдёт новую статью и проверит, что есть все 3 языка;
   - прочитает её и **предложит секцию + теги** с обоснованием;
   - спросит только то, что действительно неоднозначно (обычно один вопрос: *featured — поднять в топ секции или обычная?*);
   - покажет итоговую запись на подтверждение;
   - вставит её в реестр, пересоберёт сайт и даст отчёт;
   - предложит коммит (выполнит только после твоего «да»).

Ты только подтверждаешь или поправляешь предложенное. Команды и структуру проекта помнить не нужно.

➡️ После этого перейди к **разделу 3 (проверки)** и **разделу 5 (sitemap)**.

---

## 2. Путь B (запасной) — вручную

Используй, только если `/publish` недоступен. Делает то же самое, но руками.

### 2.1. Найти новую статью
```
node dev/generator/registry-tool.mjs detect
```
Покажет slug новой статьи и какие языки на месте. Если какого-то языка нет — статью сначала нужно дописать.

### 2.2. Подготовить запись реестра
**Запись готовит AI, не ты.** Дай ему заголовок и о чём статья:

> «Сделай запись Registry для Travel Radar LK.
> slug: `<твой-slug>`. Заголовок EN: `<...>`. О чём статья (2–3 предложения): `<...>`.
> Верни готовую JSON-строку, используя только значения из закрытых словарей проекта.»

Форма записи (поля — см. справочник в разделе 6):
```json
{ "primary_section": "weather", "country": "mexico", "region": "riviera-maya",
  "destination": "cozumel", "related_destinations": [], "content_type": "guide",
  "tags": ["best-time"], "audience": [], "featured": 0, "intent": null }
```

### 2.3. Проверить и вставить запись (безопасно, без ручной правки JSON)
```
node dev/generator/registry-tool.mjs validate '<json>'
node dev/generator/registry-tool.mjs insert <slug> '<json>'
```
`insert` сам поставит запятые и не сломает файл. Он **откажет**, если значение не из словаря, нет файла какого-то языка или slug уже есть.

> Не редактируй `dev/docs/metadata-registry.v1.json` руками — только через `registry-tool.mjs`.

### 2.4. Собрать сайт — одна команда
```
node dev/generator/build-all.mjs
```
Сама, в правильном порядке: обновит индексы → проверит совпадение трёх языков → пересоберёт все хабы → обновит меню → **пересоберёт блок «Последние материалы» на главной** (en/ru/ua). Отдельные генераторы запускать не нужно.

> **Как собирается главная (`build-home.mjs`).** Это шаг 4 внутри `build-all` (после меню). Скрипт берёт **9 самых новых** статей по дате из `content-index.<lang>.json` и перерисовывает карточки блока «Последние материалы» на `en/ru/ua/index.html`. Трогает он **только** участок между комментариями-маркерами `<!-- AUTO:latest:start -->` и `<!-- AUTO:latest:end -->` — всё остальное на главной (hero, «Как мы анализируем», карточки стран, «О проекте») не меняется. Картинка, ссылка, `alt` (= заголовок статьи), оба чипа (страна + раздел) берутся из индекса автоматически. Скрипт **идемпотентен**: гонять повторно безопасно, между публикациями диффа нет. Запускать отдельно обычно не нужно — он внутри `build-all`; но при желании: `node dev/generator/build-home.mjs` (или с одним языком: `… build-home.mjs ru`).

## 3. Проверки после сборки

В выводе команды (или в отчёте `/publish`) ищи три вещи:

1. ✅ **`warnings: 0`** у каждого языка (en/ru/uk).
   *Если есть `missing og:image` — статья попадёт в хаб с картинкой-заглушкой. Не критично, но лучше поправить картинку в `<head>`.*
2. ✅ **`✓ cross-language parity OK (en/ru/uk identical; N records each)`** — `N` должно вырасти на 1 (например 57 → 58). Значит статья опознана **во всех трёх языках**.
3. ✅ **`✓ Full rebuild complete.`**

### Убедиться, что статья в нужной секции хаба
Открой в браузере (Live Server в VS Code):
```
en/content/<секция>/index.html      # например en/content/weather/index.html
```
Карточка статьи должна быть в списке; счётчик вверху вырос на 1. Бегло глянь то же для `ru/` и `ua/`.

### Убедиться, что статья в All Hub
```
en/content/index.html
```
Новая карточка обычно вверху (сортировка по дате). Проверь также `ru/content/index.html` и `ua/content/index.html`.

### Убедиться, что статья на главной
Свежая статья автоматически попадает в блок **«Последние материалы»** на главной (9 самых новых по дате). Открой:
```
en/index.html
```
Карточка новой статьи должна быть среди девяти (обычно первой). Бегло глянь `ru/index.html` и `ua/index.html`.

> В выводе сборки ищи строки `OK: <folder>/index.html — newest 9 (...)` с галочками `✓ cards rendered: 9/9`. Если статья новее остальных, но её нет в блоке — значит не запустился `build-home.mjs` (пересобери через `build-all`).

## 3a. Блок «Начните отсюда» на главной (курируемый, вручную)

На главной над «Последними материалами» есть блок **«Начните отсюда / Start Here / Почніть звідси»** — 3 опорные карточки, которые ты выбираешь сам. Это **не** свежие статьи, а вечнозелёные гайды, с которых стоит начать новичку. Сейчас там: First-Time Mexico Vacation Planner · Cancun Hotel Booking Checklist · Mexico Travel Safety Guide.

**Важно:** этот блок **генератор не трогает** — `build-home.mjs` владеет только участком `AUTO:latest`, а курируемый блок лежит отдельно, между маркерами:
```
<!-- CURATED:start -->  …3 карточки…  <!-- CURATED:end -->
```
в `<section id="start-here">` каждого `index.html` (en/ru/ua). Пересборка сайта его не перезапишет.

**Чтобы поменять одну из трёх карточек** (заменить статью), правится вручную в 3 файлах (`en/`, `ru/`, `ua/index.html`):
1. Внутри `<!-- CURATED:start -->…<!-- CURATED:end -->` найди карточку `<a class="content-card">`, которую меняешь.
2. Замени в ней 4 вещи на данные новой статьи (возьми из `assets/data/content-index.<lang>.json` по её slug): `href="content/<slug>"`, путь к картинке `.../content/<slug>/card_1200x600.jpg`, `alt` и `<h3>` = заголовок (`title`), `<p class="content-excerpt">` = `description`, и два чипа `content-category` (страна + `section_label`).
3. Повтори то же в `ru/` и `ua/` с переводами из соответствующего индекса.

> Проще — попроси AI: «замени в курируемом блоке главной карточку X на статью `<slug>` на всех 3 языках». Он соберёт карточки из индекса и подставит. Пересобирать сайт после этого **не нужно** (блок статический), но и повторный `build-all` его не сломает.

## 4. Если сборка упала с ошибкой (`FATAL`)

Команда **намеренно останавливается и ничего не ломает**. Читай текст после `FATAL:` — он точный.

| Текст ошибки | Причина | Что сделать |
|---|---|---|
| `... article file missing: en/content/<slug>.html` | Нет файла статьи на каком-то языке, или имя не совпадает | Проверь, что все 3 файла на месте и имена идентичны |
| `missing <link rel=canonical>` / `missing og:title` / `no JSON-LD ... Article` | В `<head>` не хватает обязательного поля | Добавь поле по образцу другой статьи |
| `... out of dict: <значение>` | В запись попало значение не из словаря (опечатка) | Исправь на словарное (раздел 6) |
| `cross-language parity mismatch ... translation is likely missing` | Статья есть не во всех языках | Убедись, что все 3 файла существуют |
| `... already exists in Registry` | Такой slug уже опубликован | Это обновление — запись не нужна, просто пересобери |
| `duplicate slug` | Slug дублируется | Переименуй новую статью |

Исправил → снова `node dev/generator/build-all.mjs`. Сайт перезапишется заново начисто.

> Непонятная ошибка? Скопируй весь текст после `FATAL:` и отдай AI: «сборка упала, вот вывод — что не так?». Не редактируй файлы генераторов сам.

## 5. Sitemap — отдельный шаг, но автоматизирован скриптом

Важно знать: **ни `/publish`, ни `build-all` не трогают `sitemap.xml`.** Карта сайта правится вручную, поэтому новую статью добавляет **отдельный скрипт**. (Через `/publish` этот шаг выполняется автоматически — раздел ниже нужен, если публикуешь вручную или хочешь понимать, что происходит.)

После успешной сборки (`build-all`) запусти:
```
node dev/generator/update-sitemap.mjs
```

Что делает скрипт:
- берёт список статей и их даты из свежесобранного `assets/data/content-index.en.json` (HTML не парсит);
- дописывает в `sitemap.xml` только те статьи, чьего slug ещё нет в файле, тройкой `<url>` (en/ru/ua) перед `</urlset>`, в порядке от старой к новой; `lastmod` = `datePublished` статьи;
- **идемпотентен**: если всё уже на месте — пишет `✓ already up to date` и ничего не меняет. Запускать повторно безопасно;
- **не трогает** ~70 структурных URL (главная, `/about`, страницы стран, хабы секций) и их исторические `lastmod`; сохраняет переносы строк (CRLF).

В выводе ищи `✓ added N article(s)` (со списком slug) либо `✓ already up to date`.

> Если скрипт выдал `FATAL` — обычно это значит, что перед ним не запустили `build-all` (нет свежего `content-index.en.json`). Запусти раздел 2.4, потом повтори.
>
> Не редактируй `sitemap.xml` руками — этим владеет скрипт. Полная регенерация карты намеренно НЕ делается, чтобы не потерять исторические `lastmod` структурных страниц.

## 6. Памятка «Ежедневный Workflow владельца»

```
1. Написал статью EN → перевёл на RU и UA.
2. Сохранил 3 файла с ОДИНАКОВЫМ именем:
      en/content/<slug>.html
      ru/content/<slug>.html
      ua/content/<slug>.html
3. В Claude Code:  /publish
4. Ответил на 1 вопрос (обычно: featured — да/нет), подтвердил секцию.
5. Проверил отчёт: warnings: 0 · parity OK (N+1) · Full rebuild complete.
6. Открыл en/content/<секция>/index.html, en/content/index.html и en/index.html — карточка в хабе, в All Hub и на главной.
7. Sitemap: через /publish — автоматически; вручную — node dev/generator/update-sitemap.mjs
8. Закоммитил:  git add -A && git commit -m "Add article: <slug>"
```

Без `/publish` шаги 3–4 заменяются на раздел 2 (detect → AI готовит запись → insert → build-all), а шаг 7 — это запуск `update-sitemap.mjs` (раздел 5).

## 7. Справочник: закрытые словари

AI выбирает значения **только** отсюда. Тебе нужен в основном выбор секции.

**`primary_section` (одна, главная «полка»):**

| Секция | Когда — статья про… |
|---|---|
| `destinations` | само место: что за город/регион, районы, пляжи |
| `stay` | где жить: отели, курорты, какой район бронировать |
| `things-to-do` | чем заняться: сеноты, экскурсии, снорклинг, маршруты, дейтрипы |
| `weather` | когда ехать: сезоны, погода, ураганы, саргассум, лучший месяц |
| `planning` | логистика: бюджет, перелёты, трансферы, eSIM, страховка, визы |
| `safety` | безопасность: разводы, еда и вода, реальные риски |

*Правило при сомнении:* «какой вопрос читателя закрывает статья?» → где жить = `stay`, когда ехать = `weather`, как добраться/сколько стоит = `planning`. `news` не используется.

**Остальные поля (выбирает AI):**
- `country`: `mexico` · `egypt` · `turkey` · `dominican-republic` · `caribbean` · `generic`
- `region` или `null`: `riviera-maya` · `yucatan` · `istanbul` · `red-sea` · `punta-cana`
- `destination` или `null`: `cancun` · `tulum` · `playa-del-carmen` · `cozumel` · `isla-mujeres` · `riviera-maya` · `istanbul` · `punta-cana`
- `content_type`: `guide` · `comparison` · `listicle` · `advice`
- `audience` (список, можно пустой): `family` · `couples` · `solo` · `first-timer`
- `intent` или `null`: `inspire` · `plan` · `book`
- `featured`: `0` (обычная) или `1` (поднять в топ секции)
- `tags` (из словаря проекта): all-inclusive, adults-only, family-resort, honeymoon, boutique-hotel, cenotes, snorkeling, beaches, day-trips, theme-parks, archaeology, island-trip, airport-transfer, flights, budget, money, esim, travel-insurance, visa-entry, itinerary, booking-checklist, hurricane-season, rainy-season, sargassum, best-time, neighborhoods, hotel-mistakes, scam-warning, food-safety

## 8. Чего этот процесс НЕ делает

- Не пишет и не переводит статью — это твоя редакторская работа.
- Не трогает существующие статьи, генераторы, меню или CSS при публикации.
- Не меняет главную за пределами блока «Последние материалы» — только участок между маркерами `AUTO:latest`. Остальная вёрстка главной (hero, карточки стран, «О проекте» и будущий курируемый блок) безопасна.
- Не пушит в GitHub — публикацию/деплой ты запускаешь сам, когда решишь.
- Не регенерирует `sitemap.xml` целиком — только дописывает новые статьи скриптом (раздел 5).

---

**Краткая суть:** 3 файла статьи → `/publish` (внутри: реестр → `build-all` → `update-sitemap`) → подтвердить → проверить отчёт → коммит. Сборка попутно обновляет хабы, меню и **главную** (блок «Последние материалы»). Источник истины (`metadata-registry.v1.json` + `i18n.mjs`) и read-only статей при этом не нарушаются.
