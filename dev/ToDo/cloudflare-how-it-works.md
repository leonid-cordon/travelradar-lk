# Как работает синхронизация через Cloudflare
### Объяснение для начинающих — что мы сделали и зачем

---

## Проблема которую мы решали

До этого данные (галочки, история выполнений) хранились только в браузере на одном компьютере — в `localStorage`. Это встроенное хранилище браузера, которое живёт только на том устройстве где открыта страница.

```
БЫЛО:
ПК    → [браузер] → localStorage (своя копия данных)
Ноут  → [браузер] → localStorage (своя копия данных — другая!)
                              ↑
                    не знают друг о друге
```

```
СТАЛО:
ПК    → [браузер] → Cloudflare Worker → Cloudflare KV (одна копия данных)
Ноут  → [браузер] → Cloudflare Worker → Cloudflare KV (та же копия!)
                              ↑
                    оба видят одно и то же
```

---

## Что такое Cloudflare (коротко)

Cloudflare — это компания, у которой есть серверы по всему миру. Вы уже пользуетесь их услугами: ваш сайт `travelradarlk.com` работает через Cloudflare Pages (это хостинг статических файлов).

Но у Cloudflare есть и другие продукты. Мы использовали два из них:

- **Workers** — место где живёт программный код (мини-сервер)
- **KV** — место где хранятся данные (мини-база данных)

---

## Что такое Cloudflare KV

**KV** расшифровывается как **Key-Value** (ключ-значение).

Представьте простой словарь или блокнот:

```
ключ              → значение
-----------------------------------------
"tasks_v1"        → "[{все ваши задачи в формате JSON}]"
"settings"        → "{какие-то настройки}"
"другой_ключ"     → "другие данные"
```

Это не полноценная база данных с таблицами и SQL. Это просто хранилище пар «название → содержимое». Очень простое, очень быстрое.

Мы создали один namespace (пространство имён) с названием **DAILY_OPS_STORE**.  
Внутри него один ключ: **tasks_v1**.  
В значении этого ключа — JSON со всеми вашими задачами и историей.

```
DAILY_OPS_STORE (namespace)
└── tasks_v1  →  [{id:"001", task:"Lord Mobile...", completions:[...]}, ...]
```

Когда вы отмечаете задачу выполненной — значение ключа `tasks_v1` обновляется целиком (весь массив задач перезаписывается новой версией).

**Где это находится физически?** На серверах Cloudflare, распределённых по всему миру. Когда вы читаете данные — Cloudflare автоматически отдаёт их с ближайшего к вам сервера. Поэтому это очень быстро.

**Бесплатно ли?** Да. Бесплатный план Cloudflare включает 100,000 операций чтения и 1,000 операций записи в день. Для личного планировщика этого хватит на годы.

## Что такое Cloudflare Worker

**Worker** — это небольшая программа (код на JavaScript), которая работает на серверах Cloudflare и отвечает на запросы из браузера.

Аналогия: представьте швейцара в отеле. Вы (браузер) подходите и говорите:
- «Дайте мне мои задачи» → швейцар идёт в хранилище (KV), берёт задачи и отдаёт вам
- «Сохраните вот эти данные» → швейцар берёт данные и кладёт в хранилище

Наш Worker называется **daily-ops-api** и доступен по адресу:
```
https://daily-ops-api.leonid-cordon.workers.dev
```

Он понимает два запроса:

```
GET  /tasks  → отдать все задачи из KV
PUT  /tasks  → сохранить задачи в KV
```

Больше ничего он не делает. Очень простая программа.

## Зачем нужен Worker если есть KV?

Хороший вопрос. Почему нельзя обращаться к KV напрямую из браузера?

**Потому что KV нельзя открывать в интернет напрямую.** Если бы любой человек в мире мог читать и писать в ваше хранилище — это было бы небезопасно.

Worker стоит «перед» KV как охранник и проверяет: а имеет ли этот запрос право доступа?

```
Браузер → [запрос с токеном] → Worker → [проверка токена] → KV
                                              ↓
                               токен неверный → "Unauthorized" (отказ)
                               токен верный   → доступ к KV разрешён
```

---

## Что такое токен

Токен — это секретная строка-пароль, которую знают только ваш браузер и ваш Worker:

```
В HTML файле:   WORKER_TOKEN = '<WORKER_TOKEN>'
В Worker коде:  SECRET_TOKEN = '<WORKER_TOKEN>'
```

Когда браузер обращается к Worker-у, он добавляет этот токен в заголовок запроса:
```
Authorization: Bearer <WORKER_TOKEN>
```

Worker видит токен, сравнивает со своим, если совпадает — пропускает запрос к KV.  
Если токен не совпадает или его нет — возвращает `Unauthorized` и до KV запрос не доходит.

**Важно:** токен не секрет уровня банковского пароля, но всё равно не стоит публиковать его в открытом репозитории GitHub. Для этого в будущем можно перенести его в **Cloudflare Secrets** — специальное защищённое хранилище переменных, но для личного инструмента текущий вариант достаточно надёжен.

## Что такое Binding (привязка)

Когда мы создали KV namespace и Worker — они существовали отдельно друг от друга. Нужно было их «познакомить».

**Binding** (привязка) — это настройка которая говорит Worker-у: «вот KV namespace, обращайся к нему через переменную с таким-то именем».

Мы создали привязку:
```
Имя переменной в коде Worker-а: DAILY_OPS_STORE
Что это:                        KV namespace DAILY_OPS_STORE
```

После этого в коде Worker-а можно писать:
```javascript
await env.DAILY_OPS_STORE.get('tasks_v1')   // прочитать
await env.DAILY_OPS_STORE.put('tasks_v1', data) // записать
```

`env` — это объект со всеми привязками. Без binding-а Worker просто не знал бы что такое `DAILY_OPS_STORE`.

## Полная картина — как всё работает вместе

### Когда вы открываете страницу:

```
1. Браузер загружает daily-ops.html с travelradarlk.com
   (обычный статический файл, как картинка или CSS)

2. HTML сразу показывает задачи из localStorage
   (мгновенно, без ожидания)

3. В фоне браузер отправляет запрос:
   GET https://daily-ops-api.leonid-cordon.workers.dev/tasks
   Authorization: Bearer <WORKER_TOKEN>

4. Worker получает запрос, проверяет токен ✓

5. Worker идёт в KV:
   env.DAILY_OPS_STORE.get('tasks_v1')

6. KV возвращает JSON со всеми задачами

7. Worker отдаёт JSON браузеру

8. Браузер обновляет страницу актуальными данными
   (вы видите "✓ сохранено" на секунду)

9. Браузер сохраняет полученные данные в localStorage
   (для следующего мгновенного показа)
```

### Когда вы отмечаете задачу выполненной:

```
1. Галочка ставится мгновенно (UI обновляется сразу)

2. Данные сохраняются в localStorage (мгновенно)

3. В фоне отправляется запрос:
   PUT https://daily-ops-api.leonid-cordon.workers.dev/tasks
   Authorization: Bearer <WORKER_TOKEN>
   Body: [весь массив задач с новыми данными]

4. Worker получает, проверяет токен ✓

5. Worker записывает в KV:
   env.DAILY_OPS_STORE.put('tasks_v1', весь_массив)

6. Worker отвечает "OK"

7. В шапке мелькает "✓ сохранено" и исчезает

8. Когда ноут откроет страницу — он получит уже обновлённые данные
```

## Что мы сделали шаг за шагом

### Шаг 1 — Создали KV namespace
`Cloudflare Dashboard → Storage & databases → KV → Create namespace`

Название: `DAILY_OPS_STORE`

Это создало пустое хранилище. Как создать пустую папку.

### Шаг 2 — Создали Worker
`Workers & Pages → Create application → Worker → Start with Hello World`

Название: `daily-ops-api`

Это создало «швейцара» — пока он просто отвечал "Hello World" на любой запрос.

### Шаг 3 — Привязали KV к Worker (Binding)
`Worker → Bindings → Add binding → KV namespace`

```
Variable name: DAILY_OPS_STORE
KV namespace:  DAILY_OPS_STORE
```

Теперь Worker знает о существовании хранилища.

### Шаг 4 — Вставили рабочий код в Worker
`Worker → Edit code`

Заменили "Hello World" на настоящую логику:
- проверять токен
- отвечать на GET `/tasks` (читать из KV)
- отвечать на PUT `/tasks` (писать в KV)

### Шаг 5 — Обновили HTML
Добавили в `daily-ops.html`:
- адрес Worker-а (`WORKER_URL`)
- токен (`WORKER_TOKEN`)
- функции `pullFromWorker()` и `pushToWorker()`
- индикатор синхронизации в шапке

## Схема всего проекта

```
GitHub (исходный код)
└── leonid-cordon/travelradar-lk
    └── dev/ToDo/daily-ops.html  ← статический HTML

        ↓ git push → автодеплой

Cloudflare Pages (хостинг)
└── travelradarlk.com
    └── /dev/ToDo/daily-ops  ← страница в браузере

        ↓ fetch запросы

Cloudflare Worker (код/логика)
└── daily-ops-api.leonid-cordon.workers.dev
    └── GET /tasks  → читать данные
    └── PUT /tasks  → писать данные

        ↓ env.DAILY_OPS_STORE

Cloudflare KV (данные)
└── DAILY_OPS_STORE (namespace)
    └── tasks_v1 → [{все задачи и история}]
```

---

## Почему это надёжно

- **Данные не в браузере** — не пропадут при очистке кеша
- **Данные не в HTML файле** — обновление кода не затрагивает данные
- **Cloudflare KV** — высокая доступность, данные дублируются на нескольких серверах
- **localStorage как кеш** — страница работает даже без интернета (офлайн), просто не синхронизирует

## Если что-то сломается

**Страница показывает `⚠ офлайн`:**
- Нет интернета, или Worker временно недоступен
- Страница продолжает работать с localStorage
- При восстановлении связи — данные синхронизируются автоматически при следующем действии

**Данные «исчезли»:**
- Сделайте Экспорт — он скачает актуальные данные с KV
- Проверьте Cloudflare Dashboard → KV → DAILY_OPS_STORE → KV Pairs
- Ключ `tasks_v1` должен быть там

**Worker вернул ошибку:**
- Зайдите в Cloudflare Dashboard → Workers → daily-ops-api → Observability
- Там будут логи всех запросов и ошибок
