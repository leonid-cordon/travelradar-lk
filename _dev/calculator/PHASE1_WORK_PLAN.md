# Cancun Calculator Phase 1 Work Plan

Статус: зафиксировано перед стартом реализации  
Дата фиксации: 2026-04-07  
Проект: Travel Radar LK

## 1. Зачем этот файл

Этот файл фиксирует наши рабочие договоренности перед реализацией Фазы 1, чтобы:

- сохранить контекст после лимитов/паузы;
- сделать надежную точку опоры для бэкапа и push;
- уменьшить риск переделок между фазами;
- передать понятный handoff для продолжения работ.

## 2. Что подтвердили перед стартом

- Реализация Фазы 1 делается в текущем файле: `ru/content/cancun-budget-2026.html`.
- Прямые реальные ссылки на Booking ставим уже сейчас.
- Affiliate-слой пока отсутствует и это нормально для Фазы 1.
- Цель Фазы 1: сделать publish-ready версию, которую можно зафиксировать отдельным бэкапом/коммитом.
- Визуал можно улучшать сразу, не ограничиваясь только мелкой полировкой.
- Изменения делаем с учетом будущих Фаз 2-4, чтобы не полировать временные решения.

## 3. Пояснение по ID и итерациям

Что имелось в виду в обсуждении:

- В текущем HTML уже есть рабочие `id` и привязки JS.
- В ТЗ есть целевой набор `id` для устойчивой структуры.
- Если перейти к целевым `id` уже в Фазе 1, следующая универсализация будет проще.
- Чтобы избежать поломки в текущей версии, используем мягкую миграцию:
  - приводим разметку к целевым `id`;
  - в JS оставляем совместимость на переходном этапе;
  - после стабилизации можно убрать временную совместимость в следующих фазах.

## 4. Как делаем Фазу 1

Базовый принцип:

- делаем сразу сильную публикуемую версию;
- одновременно закладываем архитектурный фундамент под дальнейший вынос в отдельный калькулятор.

Практически:

- данные и коэффициенты приводим к конфиг-структуре;
- расчет переводим на диапазон (`min / realistic / max`);
- внедряем дату поездки, сезонность, lead-time;
- добавляем статус бюджета и объясняющие блоки;
- добавляем блоки альтернатив и экономии;
- ставим рабочие карточки/CTA с реальными ссылками;
- делаем premium и mobile polish без отрыва от текущей статьи.

## 5. Критерий фиксации Фазы 1

Версию считаем готовой к первому backup/push, когда:

- ключевые блоки Фазы 1 из `PHASES.md` реально работают;
- UX выглядит как сильный инструмент, а не черновик;
- логика и структура не мешают перейти к Фазе 2.

## 6. Следующий шаг
