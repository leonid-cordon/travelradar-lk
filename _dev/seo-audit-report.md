## Методология

**Что проверялось:**
- `<title>` — длина (рекомендация: 50–60 символов), уникальность
- `<meta name="description">` — длина (рекомендация: 130–160 символов), CTR-ориентированность
- `<link rel="canonical">` — наличие, корректность
- `hreflang` — наличие, корректность
- Теги `<h1>` — уникальность, количество на странице, соответствие title
- Структура `H2–H3` — логика, иерархия
- Открытые графики `og:title`, `og:description`, `og:image`
- Schema.org — тип разметки, обязательные поля
- `robots` — директива индексации
- Изображения — alt-атрибуты
- Внутренние ссылки — наличие, анкоры
- URL-структура — читаемость, трейлинг-слэш
- `data-page` body-атрибут — корректность

**Исключено из анализа:** /backup, /backups, /docs, /particles, системные компоненты (header, footer, layout, shared UI).

## Общая техническая база

### Сильные стороны

| Параметр | Статус |
|----------|--------|
| Тег `canonical` | Присутствует на всех проверенных страницах |
| Schema.org Article | Реализован на всех статьях (тип Article) |
| `og:type`, `og:image`, `og:url` | Присутствуют на статьях |
| `lang` атрибут на `<html>` | Корректен (ru / en / uk) |
| `meta robots: index, follow` | Присутствует на страницах стран и главных |
| `datePublished` / `dateModified` | Указаны в Schema на всех статьях |
| Google Fonts | Подключены через preconnect (оптимально) |
| Тема (dark/light) | Инициализируется до рендера (нет FOUC) |

### Системные ограничения

- Сайт — статический HTML без серверного рендеринга
- Хедер и футер загружаются через JavaScript (`load-header.js`), что делает их **невидимыми для некоторых поисковых роботов при crawl**
- Sitemap.xml присутствует и содержит корректные URL трёх версий

## Межъязыковые проблемы

### КРИТИЧНО: Отсутствие hreflang

**Файлы затронуты:** все страницы всех трёх версий

Теги `hreflang` не обнаружены ни в одной проверенной странице. Это фундаментальная проблема для мультиязычного сайта:
- Google не знает о взаимосвязи RU/EN/UA версий страниц
- Поисковики могут расценить страницы как дубли
- Пользователи могут получать нерелевантную языковую версию в результатах

**Правильный формат (должен быть в `<head>` каждой страницы):**
```html
<link rel="alternate" hreflang="ru" href="https://travelradarlk.com/ru/egypt/">
<link rel="alternate" hreflang="en" href="https://travelradarlk.com/en/egypt/">
<link rel="alternate" hreflang="uk" href="https://travelradarlk.com/ua/egypt/">
<link rel="alternate" hreflang="x-default" href="https://travelradarlk.com/en/egypt/">
```

### Непоследовательность canonical URL

| Тип страниц | С трейлинг-слэшем | Без трейлинг-слэша |
|-------------|-------------------|-------------------|
| Главные (`/ru/`, `/en/`, `/ua/`) | Да | — |
| Страны (`/ru/egypt/`, `/en/egypt/`) | Да | — |
| Статьи (`/ru/content/...`) | — | Все без слэша |

Это может создавать технические дубли (с/без слэша).

### Booking.com ссылки в EN/UA версиях

Все Booking.com ссылки на EN и UA страницах стран содержат `.ru.html`. Пример:
- EN: `href="https://www.booking.com/city/eg/hurghada.ru.html"` — НЕВЕРНО
- Должно быть: `href="https://www.booking.com/city/eg/hurghada.en-gb.html"` или без языкового суффикса

## Технические SEO-проблемы

### 1. Страницы стран Turkey и Mexico наследуют egypt-специфичные атрибуты

**Затронутые файлы:**
- `ru/turkey/index.html` — `data-page="egypt"`, `egypt-scrollspy.js`
- `ru/mexico/index.html` — `data-page="egypt"`, `egypt-scrollspy.js`
- Вероятно то же в `ua/turkey/`, `ua/mexico/`, `en/turkey/`, `en/mexico/`

### 2. Пустые alt-атрибуты на изображениях

**Затронутые файлы:**
- `ru/content/flights-egypt.html` — `alt=""` у 3 из 4 изображений

Нарушает Accessibility (WCAG 2.1) и снижает SEO-потенциал изображений.

### 3. Пустой контейнер изображения

**Затронутый файл:** `ru/content/kuda-poehat-bez-vizy.html` (строка 320)
```html
<div class="article-image"></div>
```
Пустой div без изображения — визуальный баг, сигнал незавершённости.

### 4. Неверная YouTube-ссылка на странице Мексики

**Затронутый файл:** `ru/mexico/index.html`
- Текущий плейлист (`PLG91pKDzHDRjgloQOUONts2dNUQ6chVe5`) — это плейлист Турции
- Должна быть ссылка на плейлист по Мексике

### 5. JavaScript-зависимый контент навигации

Header/footer загружаются через `load-header.js`:
- Навигационные ссылки могут быть невидимы для некоторых краулеров
- Внутренняя перелинковка через header не учитывается в PageRank-расчётах
- Частично компенсируется блоками «Читайте также» непосредственно в body

### 6. Отсутствие meta robots на статьях

На всех статьях (content/*.html) нет тега:
```html
<meta name="robots" content="index, follow">
```
На страницах стран он присутствует — непоследовательность.

### 7. Emoji в заголовках H2

В статьях про Стамбул и `kuda-poehat-bez-vizy` используются emoji в H2:
- `🏛 Султанахмет — если вы в Стамбуле впервые`
- `🌊 Кадыкёй — спокойный вариант`

Emoji в заголовках отображаются в SERP-сниппетах — может быть плюсом (выделение) или минусом (обрезание).

### 8. Несоответствие H1 и title на ряде страниц

| Страница | `<title>` | `<h1>` |
|----------|-----------|--------|
| `where-to-stay-istanbul-best-areas` | "Где остановиться в Стамбуле: лучшие районы" | "Где лучше остановиться в Стамбуле" |

## Приоритетный план улучшений

### Приоритет 1 — Немедленно (критические проблемы)

#### 1.1 Внедрить hreflang на все страницы

Добавить в `<head>` каждой страницы соответствующие теги `hreflang`.  
Подходы: ручное добавление / шаблон через load-header / sitemap-метод.

**Пример для /ru/egypt/:**
```html
<link rel="alternate" hreflang="ru" href="https://travelradarlk.com/ru/egypt/">
<link rel="alternate" hreflang="en" href="https://travelradarlk.com/en/egypt/">
<link rel="alternate" hreflang="uk" href="https://travelradarlk.com/ua/egypt/">
<link rel="alternate" hreflang="x-default" href="https://travelradarlk.com/en/egypt/">
```

**Ожидаемый эффект:** устранение риска дублей, корректное ранжирование по языкам.

#### 1.2 Исправить Booking.com ссылки на EN/UA страницах

Заменить `.ru.html` на `.en-gb.html` в EN-версиях и `.uk.html` или нейтральный URL в UA-версиях.

Примеры:
- `booking.com/city/eg/hurghada.ru.html` → `booking.com/city/eg/hurghada.en-gb.html`
- `booking.com/country/eg.ru.html` → `booking.com/country/eg.en-gb.html`

**Ожидаемый эффект:** улучшение UX для иностранной аудитории, снижение отказов.
